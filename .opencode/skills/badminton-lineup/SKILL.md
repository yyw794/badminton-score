# 羽毛球排阵（工会杯备战训练）

「男双+混双+男单+女单+女双vs混双」混合排阵，周数/人数每周变（如 2026-09-14 为 16 人 4 场地 28 场；2026-09-21 为 14 人 3 场地 21 场）。**场地约束：一个场地 2 小时 7 场 → 每轮 = 场地数 场 × 7 轮**。总能量 = 场数×4（每场固定 4 能量：双打 4 人×1、单打 2 人×2；女双vs混双也是 2v2=4 人）。**不要手排**——用回溯求解器 `solve_lineup.py` 生成，再由 `export_lineup.py` 独立硬校验并导出 Excel。

## 能量均衡铁律（最高优先，先算再排）
> 用户原话「公平(能量均衡)最重要」，见 `大模型排序需求.md`。**排任何结构前，必须先算能量算术，算不出「极差数学下限」，别动工。**
1. 总能量 = 场数×4；人均 = 总能量÷人数。
2. **极差有数学下限，且由结构锁死者（女生/锚点/单打）决定**——不是我想定多少就多少。结构一变，下限就变，以算术为准（坑 7/8）。
3. 单打给 +2，是拉大差距的最大来源：1 场固定单打让某人 +2，而别人只能靠双打 +1 追。**指定了固定单打（如 范/罗、徐/李 各 2 场）却没给对方配平手段 = 极差必然被顶大**。
4. 只有 3 个女生且其中 2 个打女单（各 +4）时，第 3 个女生最多混双补位：3 女结构的女生极差下限 = 2（徐/李=7、佳琳=5），整体极差下限 = 2。**女双vs混双每场三女同时 +1，只会同时抬高徐/李，救不了第 3 女——女双vs混双场数越多，差距越大。**（2026-09-21 实证）
5. 一旦算出目标（如 2026-09-21：14 人 84 能量、全员 [5,7]、极差 2），就把 WORK_LOW/WORK_MAX 收到这个区间内做**硬约束**，`spread_max` 设成下限，终检拒写。


## 用户最终规则（优先级顺序，改动时守住）
1. **能量 = 单打×2 + 双打×1；能量均衡是最高优先**（用户原话「公平(能量均衡)最重要」，可妥协其他软项——包括强度/胜率/女双场数，**不可**妥协能量极差）。
2. **目标：人人能量 = 总能量÷人数，极差压到结构下限**（2026-09-14 16人=7/极差2；2026-09-21 14人=6/极差2）。关于"极差下限怎么算"见上方「能量均衡铁律」，先算再排。**有极差时女生偏低端、高端全给男生**（女生有体能限制）。
3. **女生体能受限**：女生不顶满（当前 3 混双+2 女单 = 7，不再是 5 混双的 9）。女生能量由轮次模板锁死（混双数×1 + 女单数×2），**调女生能量 = 改混双轮数**，不是改选人。
4. **种子只打单打**（范智强/罗琴荩各 4 单 = 8 能量，固定），不占双打/混双槽——把双打槽让给弱手抬低端。
5. **锚点对不拆**（重组轮豁免）；**无外援 PK 外援**（每场至多 1 队含外援，外援+外援同队允许；混双每场至多 1 外援男）。
6. 男双干净组合（内部+内部/外援+外援优先，外援+内部仅兜底）——**软约束，低于能量均衡**。
7. 合练对/换搭档/保底场次 = 实例层 `pairs`/`max_pairs`/`limits.mins`（硬）。
8. 不确认的细节要反问用户，别自作主张。

## 核心分层：算法层 与 实例层（每周复用，名单会变）
- **算法层**（稳定，基本不改）：`solve_lineup.py`（回溯+剪枝+目标函数）、`export_lineup.py`（独立硬校验）。
- **实例层**（每周变）：`instances/<date>.json` = 本周接龙名单 + 锚点/种子/偏好 + 轮次结构 + 上下限/目标。`weekly.py` 读取并派生（非锚点池/外援集合）。
- **换人 = 只改那份 JSON，算法代码一行不动。** 通用算法设计见 `排阵/大模型排阵/求解器算法设计.md`（改算法前必读）。

## 运行（三步，幂等）
```bash
rm -rf 排阵/大模型排阵/__pycache__                        # 动过 solve_lineup.py 时必做
.venv/bin/python 排阵/大模型排阵/weekly.py                # ① 看本周实例派生（池/锚点/外援）对不对

.venv/bin/python 排阵/大模型排阵/export_lineup.py \
    排阵/大模型排阵/<date>-lineup.json                    # ③ 校验 + <date>-羽毛球排阵.xlsx
```
- 求解器多核并发（每核 4 重启）、85s 时间兜底，通常几秒出解；`main()` **终检能量极差 > limits.spread_max 拒写 lineup**。
- θ（BT 强度）运行时从 `scores/*/BT排名总表.xlsx` 读取，**无需手填**。
- export 打印【球员场次/能量统计】+【目标达成】+【硬校验】；全过才写 Excel。最后核对 Excel「球员统计」sheet 的能量分布。

## 能量算术（改结构前必算，结构性锁死）
通用流程：
```
① 总能量 = 轮数×场地数×4；人均 = 总能量÷人数
② 列结构定死者（轮次模板锁死，不进搜索）：
   女生   = 混双轮数×1 + 女单轮数×2  （女双vs混双轮 ×1 三女都有）
   锚点   = 出场轮数（sc_rounds / xl_rounds）
   固定单打 = 场数×2（如 范/罗 男单2=+4、徐/李 女单2=+4）
③ 自由者 = 其余人，能量和 = 总能量 − 定死者之和
④ 按定死者算出极差下限（女生第3位无单打靠混双补、上限混双场数），WORK_LOW/WORK_MAX/spread_max
   设成这个下限区间，让搜索硬件约束强制收敛
```
例1（2026-09-14，16人 4场地）：总能量 112÷16=7；种子8 / 刘严6 / 苏陈7 / 女生7 → 自由者8人算术强制全7 → 分布 6×2/7×12/8×2，**极差2**。
例2（2026-09-21，14人 3场地 21场）：总能量 84÷14=6；苏/财7、严勇文5、徐越7、李祺祺7、李佳琳5（女单2+混双补位，3女下限=2）→ 自由者 8男46能量落[5,7] → 极差2（7×7 + 5×7，总和84）。**3 女 + 女单锁 2 场结构下极差下限就是 2，排不出 1**（要 1 需全员=6，而女生无解）。
⚠️ 轮次模板不变式：**每轮恰好 = 场地数 场**（`build()` 有 assert）。重组轮把 sc+xl 两场合成 1 场 → 该轮需 `om:true` 补 1 场；**每轮至多 1 个 om**。

## 求解器关键参数（`solve_lineup.py`，每周不动）
- `WORK_MIN`（软下限）/`WORK_MAX`（硬上限）/`WORK_LOW`（硬下限）**按每周能量算术设**（先算再改，见上方铁律）：2026-09-14 为 7/8/7；2026-09-21 为 6/7/5。
- `spread_max` 从实例 `limits.spread_max` 读（=结构极差数学下限，终检拒写）。
- ⚠️ `forward_ok` 能量下限前瞻：每轮增益必须按**该球员真实可达上界**（ms 池球员可当单打对手 +2/轮，其余双打 +1/轮）。按 +1 估会把能靠 +2 达标的分支误剪死。
- 目标函数 = 强度均衡(BT θ) + `WORK_BAL_W`(2.0)×能量方差（主导）+ `WORK_FLOOR_W`×低于 WORK_MIN 平方 + `MIXED_W`(0.2)×男双混合队 − `COVERAGE_W`×互搞覆盖 + `SEED_DISTINCT_W`×种子对手重复。
- 角色挑选顺序（=优先级，别乱改）：**ms_s > xd > om > sc/xl**；候选按当前能量升序（低者优先），用户偏好只作次级条件。
- 锚点/种子/女生是构造性固定的，不进搜索；`node_cap=400000`/重启。

## 硬约束（export_lineup.py 逐条校验，违反即报错、不写 Excel）
1. 同轮不重复上场；每轮恰好 4 场（场地 6/8/17/18）。
2. 类型×性别匹配：女只能混双/女单；单打 1v1、双打 2v2。
3. 场次上下限：全员 ≤7（CAP）；非锚点 ≥4（mins 覆盖）。
4. **锚点不拆**（重组轮豁免）。
5. **无外援 PK 外援**（队级：a、b 两队都含外援才违规）。
6. 训练目标（goals/pairs/max_pairs/mins/试搭）。
7. **能量极差 ≤ limits.spread_max**（实例层设成该结构的数学下限，如 2026-09-14/2026-09-21 均为 2；`main()` 终检，>spread_max 拒写 lineup）。非 2 的下限必须先算（见能量算术），别默认 2 也别说"做不到就放宽"。

## 常见改动速查（大多数 = 改 `instances/<date>.json`，不动算法代码；改完跑三步）
- **换人/改名单** → `roster`；若换的是锚点/种子，同步 `roles`，并从 `ms_opp_internal`/`xd_prefer` 移除被移出人，确认每轮仍凑满 4 场。
- **加/减混双（=调女生能量）** → `structure.rounds[r].xd`；**加/减女单** → `ws`；**加开放男双** → `om:true`（每轮至多 1 个）。改完必验 4 场不变式 + 重算能量算术（见上节）。
- **改锚点/内战/试搭** → `roles.anchors` + `structure.sc_rounds`/`xl_rounds`/`duel_rounds`/`reshuffle_rounds`+`reshuffle_teams`（重组轮原为 sc+xl 双男双轮时须 `om:true` 补场）。
- **换种子/调种子场次** → `roles.seeds` + 各轮 `ms_seeds`（种子只打单打；改种子场次会动其能量，重算能量算术）。
- **改偏好** → `preferences.ms_opp_order`/`xd_order`/`ms_opp_cap`、`roles.ms_opp_internal`/`xd_prefer`。
- **合练对/互搞** → `pairs:[{"pair":["X","Y"],"min":N}]`（硬保底，挤占男双槽；两个含外援的组合只能"隔锚点队"互搞）。
- **试搭/重组轮** → `reshuffle_rounds`+`reshuffle_teams`。
- **换搭档** → `max_pairs:[{"pair":["P","Q"],"max":N}]`。
- **某人保底场次** → `limits.mins:{"P":N}`。
- **调能量目标/极差** → `solve_lineup.py` 的 `WORK_LOW`/`WORK_MAX`/`WORK_MIN` + 重算能量算术（`WORK_LOW` 设成自由者均值即算术强制人人同值）。
- **改场地/轮数** → `courts`/`rounds_count`（总能量随之变，重算全部算术）。

## 「无可行解」诊断（按序排查）
1. **看失败速度**：秒退（<1s，没枚举）= 过强剪枝 bug（查 `forward_ok` 的增益/池子估算，见坑 1/2）；跑满预算 = 结构紧或预算不足。
2. **大 node_cap 探针**区分预算 vs 结构：
   ```python
   import solve_lineup as S, random, time
   S.solve(S.SC_ROUNDS, S.XL_ROUNDS, S.load_theta(), random.Random(42), node_cap=8_000_000)
   ```
   找到 = 预算问题（调大生产 node_cap）；仍无 = 结构问题。
3. **验每轮 4 场不变式**（`weekly.py` 输出 / `build()` assert）。
4. **算能量算术**：结构定死者之和 vs 自由者剩余额度（如自由者 8 人×CAP 是否够、ms 槽位是否够 +2 者用）。
5. **查硬约束冲突**：组内外援上限（om 组 4 人至多 2 外援且同队）、pairs 保底 vs 男双槽、mins vs CAP、max_pairs。

## 坑清单（都真实踩过，别再踩）
1. **`forward_ok` 能量下限前瞻按"每轮 +1"估算** → 漏掉单打对手 +2，开局把全员误剪成"无可行解"（0.1s 秒退）。修成按球员真实可达增益（ms 池 +2 / 其余 +1）。（2026-09-14）
2. **剪枝条件必须是"必要条件"**：任何"必出现/必用满"假设都是过强剪枝。前科两个：①假设本轮所有外援必上场（4 外援时整树剪死）②假设每轮增益 +1。
3. **实例 JSON `_note` 中文里未转义英文双引号** → json parse error；中文引号一律用「」。
4. **改 `solve_lineup.py` 后不删 `__pycache__`** → 跑的是旧字节码，改动"不生效"。
5. **`lineup.json` 的 design_notes 是求解器自动写的**，勿手改；其措辞是**版本指纹**——拿它判断产物是不是旧代码生成的（旧产物会误导调试）。
6. **改轮次结构后不复算能量算术** → 女生/锚点/种子能量被结构性锁死，"极差"目标可能根本达不到，白跑搜索。
7. **旧规则残留**：曾以为"女生 9 局锁死不可降/极差 4 是上限"——都是旧结构（5 混双）的结论；结构一变结论就变，以能量算术为准。
8. **【2026-09-21 反省】为迁就"女双vs混双多打几场"，把女生能量顶到 8、男生 4~7、极差 4** ——违背"能量均衡最高优先"。教训：①交付前不看【能量分布】就发，错；②结构锁死女生后不重算极差下限就定 spread_max=4，错；③**女双vs混双每场三女同时 +1，只会拉大与第 3 女(无单打底仓)的差距**，要均衡就得少打、改给第 3 女混双补位。流程：改结构 → 先算能量算术+极差下限 → 再定 spread_max/WORK 区间 → 跑 → 核对分布达标才交付。

## 输出格式约定（用户已定，勿随意改）
- 主表列：轮次|场地|类型|我方|（空）|（空）|对手|**胜率参考**(A:B 取整，列宽 10.5)。
- **胜率降调性展示**：主表 "58:42"；按人 sheet 只显示「我方 58%」；底部免责声明「胜率为 BT 模型估算，仅供参考」；>75% 标 ⚠️偏悬殊。
- **按人 sheet**：每人一个 tab（人数每周变），内部按 θ 降序在前、外援随后。列=轮次|场地|类型|我方|对手|我方胜率(参考)；轮休轮标「轮休」；底部「共 N 场 / 能量 M｜免责」。
- **球员统计 sheet**：「能量消耗」列（=单打×2+双打×1），按能量降序。
- **不要**主表底部「本轮轮休…」行（已删，无意义）。
