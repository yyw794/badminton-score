# 羽毛球排阵求解器 —— 算法设计（通用）

> 本文档描述**通用算法**，不绑定任何一周的具体名单。
> 配套代码：`solve_lineup.py`（算法层·搜索）+ `weekly.py` + `instances/<date>.json`（实例层·每周数据）+ `export_lineup.py`（独立硬校验 + Excel）。
> 组织：设计原则 → 问题 → 算法 → 实例层 schema → 每周适配流程 → 局限与改进 → 代码速查。

---

## 0. 核心设计原则：算法层 与 实例层 分离（最重要）

这套系统每周复用，但**每周的名单会变**（有人请假、有人替换、外援增减）。如果把"谁参加、谁是锚点、谁是种子"硬编码进算法代码，每周一改就要动好几处代码、极易出错。所以分两层：

| 层 | 内容 | 变化频率 | 载体 |
|---|---|---|---|
| **算法层** | 回溯搜索、剪枝、候选排序、目标函数、BT 模型、分队公式 | **稳定，基本不变** | `solve_lineup.py`、`export_lineup.py` |
| **实例层** | 本周名单、锚点对、种子、偏好池、轮次结构、上下限、训练目标 | **每周变** | `instances/<date>.json`（数据） |

**换人 = 改一份 JSON，算法代码一行不动。** 这是本设计的核心收益。`weekly.py` 是两层的接口：把 JSON 读成结构化对象，并**自动派生**一些量（非锚点池、外援集合），避免手填出错。

```
微信接龙（原始数据）
   │  人工录入/生成
   ▼
instances/<date>.json（实例层：名单+角色+结构+偏好）
   │  weekly.load() 读取 + 派生
   ▼
solve_lineup.py（算法层：回溯+剪枝+目标函数）──► lineup JSON
   ▼
export_lineup.py（独立硬校验 + Excel）
```

## 1. 问题定义（通用）

**输入**：本周名单（内部男 / 女 / 外援）、BT 强度 θ、场地与轮次模板、一组硬约束与软偏好。

**输出**：`轮数 × 场地数` 场对阵（当前 7 轮 × 4 场 = 28 场），使所有硬约束满足、软偏好加权最优。

**问题分类**：**约束满足问题（CSP）+ 多目标优化**。
- **决策变量**：每个"可分配球员"（= 非锚点内部男 + 外援）在每一轮"打什么角色"（种子单打对手 / 混双男 / 开放男双 / 锚点男双对手 / 轮休）。锚点、种子、固定女是**构造性固定**的，不进搜索。
- **硬约束**（违反即非法）：同轮不重复、锚点不拆、无外援PK外援、场次上下限、指定球员混双数、局数硬上限…
- **软偏好**（违反仍合法，进目标函数扣分）：局数均衡、男双干净组合、种子遇外援、强度均衡。

**为什么难（组合爆炸）**：每轮约 10 个可分配球员往 4~10 个角色槽里放，各轮互相耦合（每人总场次/局数跨轮累计）。朴素枚举是天文数字，必须靠**剪枝 + 启发式排序**把搜索空间压到秒级。

> 实例层数据决定问题的"形状"：名单变 → 可分配池变 → 锚点/种子变 → 搜索空间变。算法层不关心具体是谁，只关心"池子有多大、约束是什么"。

## 2. 架构：求解与校验分离

```
solve_lineup.py（搜）          export_lineup.py（验）
  回溯搜索 + 目标函数     →      独立逐条重验全部硬约束
  输出 lineup JSON                全过才导出 Excel
```

**理由**：搜索代码是启发式的，容易出微妙 bug（增量计数没回滚、前瞻算错）。让一个**独立的、只读 lineup JSON 的校验器**重验所有硬约束，搜索有 bug 也不会产出错误文件。生产者/检查者分离，成本极低（校验是线性扫描），收益是正确性兜底。

**注意**：校验器读的"锚点是谁、训练目标是什么"也来自**实例层**（`weekly.load()`），所以换名单后校验标准自动跟着变——不会拿旧名单的锚点去验新名单的对阵。

## 3. 核心算法：逐轮回溯（DFS）+ 前瞻剪枝 + 多重启

### 3.1 搜索空间的结构化

不直接枚举"所有对阵"，而是利用**轮次模板**把问题切成 N 个轮次子问题（每轮独立选角），跨轮耦合通过**增量状态**传递：

```
增量状态（跨轮携带）：
  used[p]   = 球员 p 已打场次        （约束 CAP / MIN_CAP）
  work[p]   = 球员 p 已打局数        （单×2 + 双×1，约束 WORK_MAX）
  lf_xd     = 指定球员已打混双数      （目标 = 配置里的 xd_min）
  ms_f[p]   = 外援 p 当种子对手次数   （约束 MS_OPP_CAP）
```

每轮内部是一个小型 DFS：按**角色顺序**依次给每个角色挑人。

### 3.2 角色顺序 = 挑选优先级（关键设计）

每轮角色顺序即优先级——**先选的角色挑走最好的人**：

```
ms_s(种子单打对手) > xd(混双男) > om(开放男双) > sc/xl(锚点对手)
```

理由：种子单打对手、混双男有**用户指定的专属偏好池**，先选保证偏好拿得到合适的人；锚点对手是"剩余的人"，最后填。改这个顺序会显著改变结果风格。

### 3.3 候选排序启发式（引导 DFS 走向好解）

每个角色的候选不是乱序枚举，而是排好序——DFS **先尝试排最前的组合**，排序质量直接决定第一个可行解的质量：

| 角色 | 排序键 | 含义 |
|---|---|---|
| ms_s | (work 升序, 外援优先, 用户指定顺序) | 局数低的先顶；同局数按用户偏好 |
| xd | (work 升序, 用户指定顺序, 按θ) | 局数低的先顶；强非锚点优先 |
| om/sc/xl | 人:(work 升序, -θ)；组合:(局数和升序, **混合队靠后**) | 局数低先上；同局数"干净组合"在前 |

**核心思想**：把"局数均衡"（用户最高优先）做成**排序第一键**，让搜索天然倾向给局数少的人加场——均衡不靠目标函数事后优化，搜索路径本身就朝均衡走。

### 3.3b 指定合练对（`pairs`，实例层可配）

用户常要"让 X 和 Y 固定搭档打几场男双"（如 林锋+黄冬青 合练 ≥3 场）。这是**硬性的配对要求**，用三个机制保证：
- **候选排序优先**：生成 sc/xl（锚点对手，2 人组=1 队）候选时，若该组恰是某合练对且还没打满 min，把它排到最前——DFS 优先把两人凑同队。
- **前瞻 `forward_ok`**：两人能同队的后续 sc/xl 轮数（一轮至多同队 1 次）≥ 还差场数，否则剪枝。
- **终止检查**：所有合练对 `pair_cnt ≥ min` 才算解。
> 实现细节：合练对只能落在 **sc/xl**（2 人锚点对手队）；om 是 4 人拆 2 队，配对要处理拆分+外援冲突，故暂不支持（需要时再扩展）。`pair_cnt` 在选人/回滚时增量维护。

### 3.3c 互搞（合练对尽量对上锚点队，软覆盖）

用户常要"几个指定组合今晚互相打"（如 苏大哲+陈财贵 / 林锋+黄冬青 / 严勇文+刘继宇 / 罗蒙+程建兴 四组合互搞）。锚点队本就在场，非锚点合练对落在 sc/xl 时**天然对上锚点队**——所以"互搞"主要靠 §3.3b 的保底次数保证组合真的上场；再补一个**软覆盖奖励**推动"尽量对上两个锚点队"（而非只打一边）：
- **覆盖奖励**：`lineup_score` 里，每个非锚点合练对**首次**对上每个锚点队 → 减 `W_COV`。权重小（次级），局数均衡冲突时让路。
- **强度自洽**：强组合（如 林锋+黄冬青 θ积 14）对弱锚点是碾压局，① 强度项会自动让它避开碾压、只打强锚点——"互搞"要的是有来有回，不是单方面碾压，所以**不必强求**每个组合都打上两个锚点。
- **外援约束**：含外援的两个组合（如 1 外援 vs 2 外援）**不能直接对打**（每场至多 1 队含外援），它们"隔着一个锚点队"互搞即可。

> 权衡提醒：给合练对加保底场次是**硬约束**，会挤占其余球员的男双槽、可能拉低局数均衡（用户最高优先）。加之前先掂量"互搞场次 vs 局数均衡"，冲突时由用户拍板（本案例：卢志辉/陈小洪 被挤到 4 局，用户先选"互搞优先"，后投诉又改回"给卢/陈加场"，互搞降档腾槽）。

### 3.3d 重组轮（试搭：拆锚点重组）

用户常要"让 X（锚点A成员）和 Y（锚点B成员）试搭几场"（如 陈财贵[锚1] + 刘继宇[锚2] 试搭）。这**必须拆掉两个锚点对**，用"重组轮"实现：
- **结构**：实例层 `structure.reshuffle_rounds`（哪几轮）+ `reshuffle_teams`（重组成的两队，如 `[["陈财贵","刘继宇"],["苏大哲","严勇文"]]`）。
- **build**：重组轮输出 `reshuffle_teams[0] vs reshuffle_teams[1]`（优先于 duel/sc/xl 分支）。
- **solve**：重组轮**不设 sc/xl 角色**（4 个锚点全用在重组场）；保留 ms_s/xd/om。若重组轮原是 sc+xl 双男双轮（如 R3），需加 `om=true` 补回 1 场（槽位数不变）。
- **槽位守恒**：内战轮(1 男双)→重组(1 男双)；sc+xl 轮(2 男双)→重组(1)+om(1)。总男双场数不变。
- **export 校验**：⚠️ **"锚点不拆"检查对重组轮豁免**（重组轮锚点本就拆开）。
- 副产品：另一对锚点成员（如 苏大哲+严勇文）也搭上场，不坐场，通常也是好组合。

### 3.3e 换搭档（同队上限 max_pairs）& 每人场次下限（mins）

球员投诉常见两类：**"场太少"** 和 **"老跟同一个弱搭档、总输"**。
- **mins（每人场次下限）**：实例层 `limits.mins = {p: n}`，覆盖全局 `min_cap`。`weekly.min_caps` 派生 `{p: mins.get(p, min_cap)}`；求解器 `forward_ok`+终止检查用 `MIN_CAPS[p]`。用于把某几人顶到指定场次。
- **max_pairs（同队上限/换搭档）**：实例层 `max_pairs = [{"pair":[p1,p2],"max":n}]`。约束"p1、p2 同队 ≤n 次"，逼他们配不同人。求解器增量维护 `max_pair_cnt`：组 sc/xl（2 人=1 队）或 om（拆 2 队，`balanced_split`）时，若某队恰是 max pair 且已达上限 → 跳过该组。export 硬校验同队次数。
- 常配套：给被加场的人腾槽（降其它硬约束的保底，如互搞对降档）。

### 3.4 两层剪枝（提前判死）

**① 轮内剪枝 `prune(idx, taken)`**（每选一个角色调用一次）：
```
剩余可用人数 < 剩余角色所需人数   → 本轮死路
```
⚠️ **曾经的坑（实例层暴露的真 bug）**：这里曾有一句 `剩余外援数 > 剩余角色外援容量 → 死路`，它**假设本轮池里所有外援都必须上场**——但外援可以轮休！当某轮角色外援容量 < 池内外援数时（例如内战轮只有 3 个外援位、池里却有 4 名外援），这个过强剪枝会把整棵树剪死，误报"无可行解"。3 名外援时恰好不触发，所以潜伏很久；名单换到 4 名外援时立刻暴露。**教训：剪枝条件必须严格是"必要条件"，"外援可轮休"意味着该条件不成立。** 现已删除该句；组内外援上限由 `group_foreign_ok` 管，MIN_CAP 由 `forward_ok` 管。
**同类的第二个坑（2026-09-14）**：能量硬下限的前瞻曾按"每轮 +1"估算（`剩余轮数 < 还差能量 → 死路`），但单打对手每轮是 **+2**——开局即把全员误剪成"无可行解"（0.1s 秒退，特征：还没枚举就失败）。修成按每轮**最大增益**估算（ms 池 +2、其余 +1）。**教训：前瞻的"每轮增益"必须取该球员真实可达的上界，取小了就是过强剪枝。**

**② 跨轮前瞻 `forward_ok(r)`**（一轮凑齐后、进下一轮前）：
```
混双关键球员剩余需要的混双数 > 后续可用混双槽     → 死路
任一合练对：能同队的后续 sc/xl 轮 < 还差场数      → 死路
任一未来轮：可用人数(未超CAP) < 该轮需求人数      → 死路
任一球员：剩余可上场轮次 < 他还差的最少场次       → 死路（MIN_CAP）
任一球员 work > WORK_MAX                          → 死路（能量硬上限）
任一球员：剩余可上场轮次 < (WORK_LOW - work)      → 死路（能量硬下限）
```
这是 **forward checking（前瞻检查）**：在当前决策点就发现未来必然失败，立即剪掉，是"指数级不可解 → 秒级可解"的主力之一。

### 3.5 回溯的增量维护

选人和撤人都是 O(组大小) 的增量操作（`used += 1`/`used -= 1`、`work += 2`/`work -= 2`…），**不在每个节点重算全局状态**。漏掉任何一处回滚都会污染后续候选（经典 bug 源，所以有独立校验器兜底）。

### 3.6 多随机重启 + 取最优（best-of-N）

```
rng = 固定种子（可复现）
for i in 1..N:
    shuffle(球员枚举顺序)
    跑一次 DFS（找到第一个可行解即停）
    best = min(best, 目标函数(解))
```

每次重启 shuffle 枚举顺序 → DFS 第一解不同 → N 个可行解里取目标函数最优。**这是随机重启，不是全局优化**：每次重启内部找到第一个可行解就停。质量 = 排序启发式的底子 + 重启多样性的补充。

### 3.7 节点预算与时间兜底

`node_cap`（单次重启搜索节点上限，防某顺序特别差时陷死）+ deadline（软，重启循环里检查）+ SIGALRM（硬，杀进程）双保险，超时采用当前最优。

## 4. 目标函数（软约束的加权求和）

硬约束靠搜索保证，软偏好折算成一个标量分数（越小越好）：

```
score =
    Σ 每场 |max(p, 1-p) - 0.5|          # ① 强度均衡：胜负概率越接近 50% 越好
  + W_MIXED × 男双混合队数               # ② 干净组合偏好（外援+内部队扣分）
  + W_SEEDDIST × 种子单打对手重复数       # ③ 种子对手风格多样（软）
  + W_BAL   × Σ(work[p] - avg)²          # ④ 局数均衡：方差惩罚（主导项）
  + W_FLOOR × Σ max(0, WORK_MIN - work[p])²  # ⑤ 低于下限者平方惩罚（防坐冷板凳）
  - W_SEED  × 种子遇外援的单场数          # ⑥ 用户指定对手偏好（弱奖励）
  - W_COV   × 互搞覆盖数(非锚点合练对首次对上锚点队)  # ⑦ 互搞覆盖（软：尽量对上）
```

**权重设计原则**：
- **权重比 = 优先级比**。`W_BAL×方差` 远大于 `W_MIXED×混合队`，保证"局数均衡冲突时局数平衡优先"（用户明确要求的顺序）。
- `W_FLOOR×平方` 比方差项更陡：方差平均摊薄，平方惩罚集中打击最惨的那个人。
- 硬上限 `WORK_MAX` 不进目标函数，而是**剪枝里直接砍**（硬约束归硬约束，不靠权重堆）。
- `W_COV`（互搞覆盖）/ `W_SEEDDIST`（种子对手多样）是**小权重次级项**：只在局数均衡不打架时起引导作用，冲突时让路。

> 权重是**算法层**参数（每周不动）；"哪些偏好、偏好谁"是**实例层**数据（每周可改）。

## 5. 强度模型：Bradley-Terry

胜负概率用 **BT 模型**（Elo 族，从历史比分最大似然估计的 θ）：
```
单打：p(A胜) = θA / (θA + θB)
双打：队伍强度 = θ₁ × θ₂（θ 乘积近似）
```
θ 运行时从 `scores/*/BT排名总表.xlsx` 读取，战绩更新后自动生效，**无需进实例层**。（实例层只放"本周谁参加"，θ 是"球员实力"，二者解耦。）

---

## 6. 子结构用闭式贪心（小规模子问题不开搜索）

每个搜索节点再开一层搜索会爆炸，所以"把已选的人分队"的子问题用确定性公式秒解：
- **开放男双 4 人分 2 队**：若含 2 外援 → 强制同队（无外援PK外援）；否则 θ 排序首尾配对（两队 θ 积最接近）。
- **混双 2 男配 2 固定女**：两种配对各算一次 |θ积差|，取差小的。

原则：**能用排序/公式解决的子结构，绝不进搜索树。**

## 7. 硬约束的编码方式（对照代码，通用）

| 约束 | 编码位置 | 方式 |
|---|---|---|
| 每轮恰好 `场地数` 场 | 实例层 `structure.rounds` + `build()` 的 assert | 结构保证（配置错了会 fail-fast） |
| 锚点不拆 | 实例层 `roles.anchors`；模板里锚点**整队**上场 | 构造性满足 |
| 无外援PK外援 | `group_foreign_ok` + `ROLE_FOREIGN_CAP`（组内上限）+ 分队公式（2 外援同队） | 搜索过滤 |
| 同轮不重复 | `taken` 集合 | 搜索过滤 |
| 场次上下限 | `CAP`（入池条件）+ `MIN_CAP`（前瞻+终止检查） | 搜索剪枝 |
| 指定球员混双数 | `lf_xd` 计数 + 前瞻 + 终止检查 | 搜索剪枝 |
| 能量硬上限 | `work > WORK_MAX(=8)` 前瞻砍+终止检查 | 搜索剪枝 |
| 能量硬下限 | `work < WORK_LOW(=7)` 前瞻砍+终止检查 | 搜索剪枝 |
| 能量极差≤2（目标全员=7） | 结构定死者：种子4单=8/刘严R4休=6/苏陈=7/女生3混双+2女单=7；非锚点非种子 WORK_LOW=7 + 总能量守恒(112=16×7) ⇒ 算术强制全=7；`main()` 终检，>2 拒写 lineup | 构造性+终检（硬） |
| 重组轮(试搭) | 实例层 `structure.reshuffle_rounds/teams`；`build()` 重组分支 + `solve()` 免 sc/xl | 构造性 + 校验豁免 |
| 换搭档(同队上限) | 实例层 `max_pairs`；`max_pair_cnt` + 组过滤 | 搜索过滤（硬） |
| 每人场次下限 | 实例层 `limits.mins`；`weekly.min_caps`→`MIN_CAPS` | 搜索剪枝（硬） |
| 类型/性别/场地/名单 | **只在 export 校验** | 独立校验 |

模式：**能在数据结构上"构造性满足"的约束（锚点整队、场地按序 zip），就不写运行时检查**——比运行时判断更不容易错。

## 9. 每周适配流程（接龙 → 对阵表）

1. **录入接龙**：把本周接龙名单写进 `instances/<date>.json` 的 `roster`（新建一份，保留历史周做版本对比）。
2. **指派角色**（策略决策，可能需人确认）：锚点对、种子、偏好池。⚠️ 若**被替换的恰好是锚点/种子**，这不是纯数据替换，而是策略问题——要重新决定锚点谁和谁锁队，并检查 `structure` 每轮仍凑满场地数。
3. **自检**：`python weekly.py` 看派生池/锚点/外援对不对。
4. **求解**：`python solve_lineup.py` → 若"无可行解"，先怀疑实例层（结构凑不满/某人被锁死），再用更大 `node_cap` 排除"搜索预算不足"。
5. **校验+导出**：`python export_lineup.py` 看【目标达成】+【硬校验】。

### 案例：陈顺星 → 黄冬青（2026-09-14）
- 接龙里内部锚点 **陈顺星** 被外援 **黄冬青**（θ≈3.91，很强）替换。
- 数据层改动（`roster` + `roles.anchors` 换第二锚点 + 偏好池移出新锚点成员）**几分钟完成**。
- 跑求解器 → **误报"无可行解"** → 定位到 §3.4 的过强剪枝 bug（4 名外援 > 内战轮 3 个外援位）→ 修掉后秒解，且混合队比旧名单还少。
- **价值**：分离架构让"换人"变成可 diff 的数据编辑；同时把"结构性无解 vs 代码 bug"变成了可快速二分的问题（换配置能解 = 代码 bug，怎么换都无解 = 结构问题）。

### 案例：黄冬青临时退出 → 3 场地 14 人 + 能量均衡（2026-09-21）
- 名单 15→14 后，每轮必须=场地数(3)场；R7 原"开放男双"需 12 男 > 11 男 → 结构改成 R7 混双。
- **能量算术先于结构**：84/14=6.0；3 女生中 徐越/李祺祺 各有女单 +4 底仓，李佳琳 无 → 推得女生极差下限=2（7/7/5）、整体下限=2、要"极差 1"= 全员恰好 6 无解。据此把 `spread_max=2`、`WORK_LOW=5/WORK_MAX=7` 收成硬约束。
- **女双vs混双的坑**：每场三女同时 +1，只会同步抬高有女单底仓的徐/李、救不了李佳琳 → 从 3 场降到 1 场，改用 4 场混双（李佳琳全上）补位，最终 7×7 + 5×7 的极差 2。
- **教训固化**：交付前必须核对【球员能量统计】；结构/名单一变就重算能量算术与极差下限，不许默认 spread_max=4 或"做不到就放宽"。

## 10. 为什么不用 ILP / CP-SAT

| 维度 | 手写回溯 | 通用求解器 |
|---|---|---|
| 规模 | 十几人 × 7 轮，小 | 为大规模设计 |
| 领域启发式 | 角色优先级/局数增量/偏好池**直接写进搜索** | 要译成 0/1 变量，启发式表达力弱 |
| 目标函数 | 任意非线性（平方惩罚、θ 乘积）随手写 | 线性/凸之外要拆变量 |
| 依赖 | 零（纯 stdlib） | 装求解器 |

小规模 + 强领域知识 + 零依赖诉求下，手写 DFS 是更优工程选择。若规模扩到几十人/轮次或要"证明最优"，换 CP-SAT。

## 11. 已知局限与改进方向

1. **每重启只取第一解，不做分支定界** → 可能漏掉显著更优解。改进：`rec` 里加"当前分支分数下界 ≥ best 就剪"。
2. **局数排序是近视贪心** → 不保证全局方差最小。改进：迭代局部搜索（swap 邻域）。
3. **重启次数固定** → 预算内可加，收益递减。
4. **θ 乘积是近似** → 双打默契/身高差不在模型里。
5. **结构性无解依赖人工二分** → 可加一个"松弛诊断"：逐个放宽硬约束，定位是哪条卡死（本次剪枝 bug 就是靠"换配置仍无解=代码问题"的思路定位的）。

## 13. 学习路线建议

1. **先跑起来**：`python weekly.py`（看派生）→ `python solve_lineup.py` → `python export_lineup.py`。
2. **读代码顺序**：`weekly.py`（实例层）→ `solve()` 的 roles 构造 → `rec()`（排序+剪枝+回滚）→ `forward_ok` → `lineup_score` → `main()`。
3. **动手实验**（改完重跑三步验证）：
   - 调 `W_MIXED`（干净组合权重）大→混合队减少但局数均衡变差，体会"权重=优先级"；
   - 调 `W_BAL`→0，观察局数极不均衡但强度更平均；
   - 换一份实例（改 `roster`/`anchors`），观察算法层零改动即适应；
   - 重启 N 调大，观察分数是否继续下降（best-of-N 天花板）。
4. **进阶**：按 §11.1 给 `rec` 加分支定界，对比 best-of-N 结果差异。
